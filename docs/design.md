# 関所めぐり（@shiodome47/sekisho）の設計

> 状態: **壁打ち中**。決まったことから書いていく。「案」と書いたところは、まだ決まっていない。

## これは何か

チェックリストをクリアしていく「関所めぐり」の部品。いろいろなアプリに入れて使う。
最初に入れるのは手話学習アプリ（shiodome47/shuwa-video-player）。次は英語アプリなど。

- チェック項目に全部チェックが入ると、その関所はクリア。「関所クリア！」の演出とご褒美が出る
- コースには 2 種類ある
  - **与えられたコース**: 教える側（管理者）が作って配る
  - **自分のコース**: 自分で作る（「この動画」「これを 10 回くり返す」など）
- 回り方は、順番に回る形と、どこから回ってもよい「ロゲイニング」の形

## 言葉

| 言葉 | コードの名前 | 意味 |
|---|---|---|
| コース | `Course` | 関所の集まり。回り方（順番・ロゲイニング）を持つ |
| 関所 | `Gate` | チェック項目のまとまり。全部済んだらクリア |
| チェック項目 | `CheckItem` | 1 つのやること。中身（動画・区間・文字など）は部品は知らない |
| 進み具合 | `Progress` | その人が、どの項目にチェックを入れたか |
| クリアの記録 | `GateClear` | その人が、どの関所をいつクリアしたか |
| ご褒美 | `Reward` | クリアしたときの演出。コネクタ（差込口）でつなぐ |

## 決まったこと

### 1. 名前と置き場所（決定）

- リポジトリ: `shiodome47/sekisho`（単独）。catalog の決まり「ほかと関係なく育つものは単独のリポジトリ」に合わせた。

### 2. データの形（決定。細かいところは作りながら直す）

大きな考え方:

- コースの**設計**（だれが見ても同じ）と、その人の**進み具合**（人ごと）を分けて持つ。
  こうすると、管理者がコースを新しい版にしても、進み具合は消えない
- 与えられたコースと自分のコースは**同じ形**。違いは `origin`（どこから来たか）だけ
- 関数はデータを書き換えず、変更を返す。保存はアプリがする（planner と同じやり方）
- 「今」（`now`）は関数に渡す。日付は端末の時刻で数える（YYYY-MM-DD）

```ts
/** コース（設計） */
interface Course {
  id: string
  title: string
  description?: string
  /** 'given' 与えられた（読むだけ）／'own' 自分で作った */
  origin: 'given' | 'own'
  /** 回り方。'free' どこからでも（既定）／'ordered' 順番 */
  route?: 'free' | 'ordered'
  gates: Gate[]
  /** 設計の版。管理者が直すと上がる */
  revision: number
  createdAt: string
  updatedAt: string
}

/** 関所 */
interface Gate {
  id: string
  title: string
  description?: string
  items: CheckItem[]
  /** 点数。今は使わない（あとで足す場所） */
  points?: number
  /** この関所のご褒美（4 番で決める） */
  reward?: RewardRef
}

/** チェック項目 */
interface CheckItem {
  id: string
  /** 表示する文（「あいさつの区間を 10 回」など） */
  title: string
  note?: string
  /**
   * 中身へのつなぎ。部品は中を見ない。アプリが表示と「開く」をする。
   * 例: { type: 'segment', id: '…' }（手話アプリの区間）、{ type: 'lesson', id: '…' }（動画）、
   *     無し（文字だけ）
   */
  target?: { type: string; id?: string; [key: string]: unknown }
  /** くり返す回数（「10 回」）。無ければ 1 回（チェックを入れるだけ） */
  count?: number
  /** チェックが外れるか。今は使わない（あとで 'daily' 毎日 などを足す場所） */
  repeat?: never
}

/** 進み具合（1 人・1 チェック項目につき 1 件） */
interface ItemProgress {
  /** `${courseId}|${itemId}` */
  id: string
  courseId: string
  itemId: string
  /** 今の回数（count のある項目） */
  done: number
  /** 済んだ日時 */
  checkedAt?: string
  updatedAt: string
}

/** クリアの記録（1 人・1 関所につき 1 件） */
interface GateClear {
  /** `${courseId}|${gateId}` */
  id: string
  courseId: string
  gateId: string
  clearedAt: string
}
```

コースが新しい版になったとき（管理者が配り直したとき）:

- 進み具合はチェック項目の `id` で結びつける。消えた項目の進み具合は使わない（残してもよい）
- 新しく足された項目は、まだの状態で出る
- 一度クリアした関所は、項目が足されてもクリアのまま

チェックの入れ方・外し方（決定）:

- チェックは **1 回きり**。一度済んだら、日付が変わっても外れない
- まちがえたときは、**自分で外せる**（回数のある項目は 1 つ戻せる）
- 関所の**クリアは消えない**。項目を外しても、クリアの記録（`GateClear`）は残す。
  もう一度全部そろっても、演出は 2 回目は出さない
- 「毎日やり直す項目」は今は入れない。あとで足せるように `repeat` の場所だけ空けておく

回数のある項目（「10 回くり返す」）の数え方（決定）:

- 画面には「3 / 10」のように出す。**押すたびに 1 つ進む**。10 に届いたら済み
- 「まとめて済みにする」もできる（10 回やったあとで開いたときなど）
- 自動のチェック（区間を 1 回くり返した、など）も、同じ数に 1 つずつ足す（5 番）

画面のイメージ（関所 1 つ分）:

```
┌ 第 1 の関所：あいさつ ───────── 2 / 3 ┐
│ ✅ 「おはよう」の動画を見る              │
│ ✅ 「こんにちは」の区間を見る            │
│ ◻ 「ありがとう」の区間を 10 回  [ 3 / 10 ＋ ] │
└──────────────────────────┘
   ↓ 最後の項目が 10 / 10 になると
   🎉 関所クリア！（演出とご褒美）
```

### 3. 回り方（決定）

- 回り方は**コースごとに選ぶ**
  - **どこからでも（`free`。既定）**: 関所は全部見えていて、どれからクリアしてもよい（ロゲイニングの形）。
    並びは「おすすめの順」として出すだけ
  - **順番（`ordered`）**: 前の関所をクリアすると、次の関所が開く。まだの関所は名前を見せて 🔒
- ご褒美は**関所を 1 つクリアするたびに出す**。コースを全部クリアしなくてももらえる
- コースを全部クリアしたときは、もう一段大きい演出を出す（4 番で決める）
- 点数は今は入れない。あとで足せるように `Gate.points` の場所だけ空けておく

```
どこからでも                      順番
🏯 あいさつ   ✅ クリア            🏯 あいさつ   ✅ クリア
🏯 数字       ▶ 2 / 5             🏯 数字       ▶ 2 / 5
🏯 家族       ✅ クリア            🔒 家族
🏯 天気       ▶ 0 / 4             🔒 天気
```

関所が開いているか（`isGateOpen`）:

- `free`: いつも開いている
- `ordered`: 最初の関所か、1 つ前の関所にクリアの記録がある
  （順番のコースで、あとから前に関所が足されても、もうクリアした関所は開いたままにする）
