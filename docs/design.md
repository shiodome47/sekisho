# 関所めぐり（@shiodome47/sekisho）の設計

> 状態: **壁打ち中**。決まったことから書いていく。「案」と書いたところは、まだ決まっていない。

## これは何か

チェックリストをクリアしていく「関所めぐり」の部品。いろいろなアプリに入れて使う。
最初に入れるのは手話学習アプリ（shiodome47/shuwa-video-player）。次は英語アプリなど。

- チェック項目に全部チェックが入ると、その関所はクリア。「関所クリア！」の演出とご褒美が出る
- コースには 2 種類ある
  - **与えられたコース**: 教える側（管理者）が作って配る
  - **自分のコース**: 自分で作る（「この動画」「これを 10 回くり返す」など）
- 回り方は、順番に回る形と、どこから回ってもよい「ロゲイニング」の形

## 言葉

| 言葉 | コードの名前 | 意味 |
|---|---|---|
| コース | `Course` | 関所の集まり。回り方（順番・ロゲイニング）を持つ |
| 関所 | `Gate` | チェック項目のまとまり。全部済んだらクリア |
| チェック項目 | `CheckItem` | 1 つのやること。中身（動画・区間・文字など）は部品は知らない |
| 進み具合 | `Progress` | その人が、どの項目にチェックを入れたか |
| クリアの記録 | `Clear` | その人が、どの関所（とコース）をいつクリアしたか |
| ご褒美 | `Reward` | クリアしたときの演出。コネクタ（差込口）でつなぐ |

### 2. データの形（決定。細かいところは作りながら直す）

大きな考え方:

- コースの**設計**（だれが見ても同じ）と、その人の**進み具合**（人ごと）を分けて持つ。
  こうすると、管理者がコースを新しい版にしても、進み具合は消えない
- 与えられたコースと自分のコースは**同じ形**。違いは `origin`（どこから来たか）だけ
- 関数はデータを書き換えず、変更を返す。保存はアプリがする（planner と同じやり方）
- 「今」（`now`）は関数に渡す。日付は端末の時刻で数える（YYYY-MM-DD）

```ts
/** コース（設計） */
interface Course {
  id: string
  title: string
  description?: string
  /** 'given' 与えられた（読むだけ）／'own' 自分で作った */
  origin: 'given' | 'own'
  /** 回り方。'free' どこからでも（既定）／'ordered' 順番 */
  route?: 'free' | 'ordered'
  gates: Gate[]
  /** 設計の版。管理者が直すと上がる */
  revision: number
  createdAt: string
  updatedAt: string
}

/** 関所 */
interface Gate {
  id: string
  title: string
  description?: string
  items: CheckItem[]
  /** 点数。今は使わない（あとで足す場所） */
  points?: number
  /** スタンプの見た目。無ければ名前の 1 文字目・コースの色 */
  stamp?: { text?: string; color?: string }
  /** この関所のご褒美。無ければスタンプだけ */
  reward?: RewardRef
}

/** チェック項目 */
interface CheckItem {
  id: string
  /** 表示する文（「あいさつの区間を 10 回」など） */
  title: string
  note?: string
  /**
   * 中身へのつなぎ。部品は中を見ない。アプリが表示と「開く」をする。
   * 例: { type: 'segment', id: '…' }（手話アプリの区間）、{ type: 'lesson', id: '…' }（動画）、
   *     無し（文字だけ）
   */
  target?: { type: string; id?: string; [key: string]: unknown }
  /** くり返す回数（「10 回」）。無ければ 1 回（チェックを入れるだけ） */
  count?: number
  /** チェックが外れるか。今は使わない（あとで 'daily' 毎日 などを足す場所） */
  repeat?: never
}

/** 進み具合（1 人・1 チェック項目につき 1 件） */
interface ItemProgress {
  /** `${courseId}|${itemId}` */
  id: string
  courseId: string
  itemId: string
  /** 今の回数（count のある項目） */
  done: number
  /** 済んだ日時 */
  checkedAt?: string
  updatedAt: string
}

/** クリアの記録（1 人・1 関所につき 1 件。gateId が無いものはコースを全部クリアした記録） */
interface Clear {
  /** `${courseId}|${gateId}`、コースは `${courseId}|*` */
  id: string
  courseId: string
  gateId?: string
  clearedAt: string
}
```

コースが新しい版になったとき（管理者が配り直したとき）:

- 進み具合はチェック項目の `id` で結びつける。消えた項目の進み具合は使わない（残してもよい）
- 新しく足された項目は、まだの状態で出る
- 一度クリアした関所は、項目が足されてもクリアのまま

チェックの入れ方・外し方（決定）:

- チェックは **1 回きり**。一度済んだら、日付が変わっても外れない
- まちがえたときは、**自分で外せる**（回数のある項目は 1 つ戻せる）
- 関所の**クリアは消えない**。項目を外しても、クリアの記録（`Clear`）は残す。
  もう一度全部そろっても、演出は 2 回目は出さない
- 「毎日やり直す項目」は今は入れない。あとで足せるように `repeat` の場所だけ空けておく

回数のある項目（「10 回くり返す」）の数え方（決定）:

- 画面には「3 / 10」のように出す。**押すたびに 1 つ進む**。10 に届いたら済み
- 「まとめて済みにする」もできる（10 回やったあとで開いたときなど）
- 自動のチェック（区間を 1 回くり返した、など）も、同じ数に 1 つずつ足す（5 番）

画面のイメージ（関所 1 つ分）:

```
┌ 第 1 の関所：あいさつ ───────── 2 / 3 ┐
│ ✅ 「おはよう」の動画を見る              │
│ ✅ 「こんにちは」の区間を見る            │
│ ◻ 「ありがとう」の区間を 10 回  [ 3 / 10 ＋ ] │
└──────────────────────────┘
   ↓ 最後の項目が 10 / 10 になると
   🎉 関所クリア！（演出とご褒美）
```

### 3. 回り方（決定）

- 回り方は**コースごとに選ぶ**
  - **どこからでも（`free`。既定）**: 関所は全部見えていて、どれからクリアしてもよい（ロゲイニングの形）。
    並びは「おすすめの順」として出すだけ
  - **順番（`ordered`）**: 前の関所をクリアすると、次の関所が開く。まだの関所は名前を見せて 🔒
- ご褒美は**関所を 1 つクリアするたびに出す**。コースを全部クリアしなくてももらえる
- コースを全部クリアしたときは、もう一段大きい演出を出す（4 番で決める）
- 点数は今は入れない。あとで足せるように `Gate.points` の場所だけ空けておく

```
どこからでも                      順番
🏯 あいさつ   ✅ クリア            🏯 あいさつ   ✅ クリア
🏯 数字       ▶ 2 / 5             🏯 数字       ▶ 2 / 5
🏯 家族       ✅ クリア            🔒 家族
🏯 天気       ▶ 0 / 4             🔒 天気
```

関所が開いているか（`isGateOpen`）:

- `free`: いつも開いている
- `ordered`: 最初の関所か、1 つ前の関所にクリアの記録がある
  （順番のコースで、あとから前に関所が足されても、もうクリアした関所は開いたままにする）

### 4. ご褒美（決定）

クリアしたときの流れ:

```
関所の最後の項目が済む
  → ① 通行手形にスタンプが「ポン！」と押される（部品に入っている。いつも出る）
  → ② その関所のご褒美（gate.reward）があれば、続けて出す（コネクタ）
  → コースの関所を全部クリアしたら、③ 手形がそろった大きい演出 ＋ course.reward
```

- 部品に最初から入れる演出は**通行手形のスタンプ**だけ
  - 関所ごとの印（丸い印に 1〜2 文字。既定は関所の名前の 1 文字目）
  - 押した印はコースの画面（通行手形）に残る。あとで眺められる
- ご褒美は**関所ごとに決められる**（`gate.reward`）。無ければスタンプだけ。コースにも付けられる（`course.reward`）
- 紙吹雪・効果音・振動は、あとから同じコネクタで足せる

ご褒美のコネクタ（差込口）の形:

```ts
/** ご褒美の指定（コースの JSON に書く）。type で、どのコネクタが出すかを決める */
interface RewardRef {
  type: string               // 'message' ひみつの一言（部品に入れる）、'video' 動画（アプリが足す）など
  [key: string]: unknown     // コネクタが使う中身（動画の id・一言の文など）
}

/** クリアの知らせ（コネクタが受け取る） */
interface ClearEvent {
  kind: 'gate' | 'course'
  course: Course
  gate?: Gate
  cleared: number            // クリアした関所の数
  total: number              // 関所の数
  at: string
}

/** コネクタ。アプリが <Sekisho rewards={[...]} /> のように渡す */
interface RewardConnector {
  type: string
  /** 画面に出すもの。done() を呼ぶと次へ進む（閉じる） */
  render: (props: { reward: RewardRef; event: ClearEvent; done: () => void; reducedMotion: boolean; muted: boolean }) => ReactNode
}
```

- 部品に入れるコネクタ: `message`（ひみつの一言を出す）
- スタンプの演出そのものも `renderStamp` で差し替えられる（英語アプリでメダルにする、など）
- 手話アプリが足すコネクタ: `video`（先生の「おめでとう」の手話動画を出す）
- 知らない `type` のご褒美は飛ばす（古い版のアプリでも止まらない）
- **演出を減らす設定**（端末の prefers-reduced-motion か、アプリの設定）: スタンプは動かさずに表示だけ。
  **音を消す設定**: コネクタに `muted` を渡す。手話アプリでは音は既定で消しておく

### 5. 自動のチェック（決定）

部品は「何をしたら数えるか」を知らない。アプリが「これをした」と知らせる差込口だけを用意する。

```ts
/** アプリが知らせる「これをした」。target はチェック項目の target と同じ形 */
interface Activity {
  target: { type: string; id?: string }
  /** 何回分か。無ければ 1 */
  amount?: number
}

/** 知らせを受けて、進み具合の変更を返す（データは書き換えない。保存はアプリ） */
function report(data: SekishoData, activity: Activity, now: Date): Changes
// Changes には、進んだ項目（ItemProgress）と、新しくクリアした関所（Clear）が入る。
// 新しいクリアがあれば、画面の部品がスタンプとご褒美を出す
```

- `target` の `type` と `id` が同じチェック項目を、**入っているコース全部**で 1 つずつ進める
  （回数の無い項目なら、済みにする）
- 数えるのは**コースを入れてから**の分だけ。前の練習の記録はさかのぼらない
  （知らせはその場で受けるだけなので、自然にそうなる）
- 自動で数える項目でも、**自分で「＋1」「済み」も押せる**（アプリの外で練習したときのため）
- 順番のコースで、まだ開いていない関所の項目は進めない

手話アプリでのつなぎ方（例）:

| アプリで起きたこと | 知らせ |
|---|---|
| 区間を 1 回くり返した（B から A に戻った。今の `noteLoop()`） | `{ target: { type: 'segment', id: 区間の id } }` |
| 動画を最後まで見た（あとで足すかも） | `{ target: { type: 'lesson', id: 動画の id } }` |

英語アプリなら、例文の暗唱が済んだときに `{ type: 'sentence', id }` を知らせる、のように使う。

### 6. コースの作り方・配り方（決定）

- **自分のコースを作る画面と、管理者がコースを作る画面は同じ**。1 つの画面で両方に使う
  - 学ぶ人: 作ったコースは自分のコース（`origin: 'own'`）として回る
  - 管理者: 作ったコースを書き出して配る。受け取った人のところでは、与えられたコース（`origin: 'given'`）になる
- 与えられたコースは、学ぶ人には**読むだけ**（チェックは入れられる）。「複製して自分のコースにする」はできる
- 管理者が直して配り直すと、同じ `id` のコースが新しい版（`revision` が上がる）になる。進み具合は残る（2 番）
- 関所の並べ方は **linkshelf の `<CardBoard>`**。関所をカードにして段組みで並べ、ドラッグで動かす
  - 作る画面だけの入り口（`@shiodome47/sekisho/editor`）にして、linkshelf はそこでだけ使う。
    回るだけの画面（`@shiodome47/sekisho`）は linkshelf が無くても動く
  - カードの中で、チェック項目を足す・直す・並べ替える・消す
- チェック項目の中身（動画・区間など）を選ぶのはアプリ。部品はアプリの窓口を呼ぶだけ:

```ts
interface TargetAdapter {
  /** 「動画・区間を選ぶ」を押したとき。アプリが自分の画面で選ばせ、選んだものを返す（やめたら null） */
  pick?: () => Promise<{ target: CheckItem['target']; title: string } | null>
  /** 項目の横に出す小さな印（▶ 動画、🔁 区間 など） */
  renderBadge?: (target: CheckItem['target']) => ReactNode
  /** 項目を押したとき、その中身を開く（手話アプリなら、動画や区間に飛ぶ） */
  open?: (target: CheckItem['target']) => void
}
```

- 文字だけの項目（「これを 10 回くり返す」）は、部品の画面だけで作れる
- 配り方: 手話アプリでは**パック**にコースを入れる（パックの `data` に「無くてもよい項目」として足す）。
  コースの項目が区間を指しているときは、**その区間もパックに入れる**必要がある（今のパックは区間を運ばない。7 番で手話アプリ側の作業にする）
- 部品は書き出し・読み込みの関数（JSON）だけを持つ。パックの形はアプリが決める

### 7. 手話アプリでどこに出すか（決定）

- 当分は依頼者だけで楽しむので、**隠しページ**にする
  - 新しいページ「関所」（`/sekisho`）。メニューには出さない
  - 入り口は**設定のページのいちばん下**に、小さな灰色の文字のリンクを 1 つだけ置く
  - ページの中: コースの一覧・通行手形（スタンプ）・コースを作る画面
- ホームのカード・区間の画面での知らせ・「関所に足す」ボタンは、みんなに出すときに考える
- 隠しページでも、データはきちんと残す
  - 保存先は ShuwaDB の新しい表（コース・進み具合・クリアの記録）。同期・バックアップに乗せる
  - `docs/data-model.md` の「後から表を足すときの決まり」を守る（古い版との互換）
- 自動のチェックは最初からつなぐ: 区間を 1 回くり返したら（今の `noteLoop()`）、`report({ target: { type: 'segment', id } })`
- パックでコースを配るのは、みんなに出すときに足す（区間もパックに入れる作業と一緒に。practice-kit の作業と相談する）
